# Atomic Drift Tuner v0.8.2-beta.1 — Reliability & Recovery

This beta focuses on reliability across saved data, telemetry, AC setup generation, and SimHub/AZOM Apply/Revert. The existing ADT workflow and roadmap remain intact.

## Changes

- Stronger validation and recovery for settings, saved profiles, calibration and revert records.
- Stale AZOM Apply/Revert plans are refused when live values have changed since review. Remote undo cannot overwrite a newer setting change.
- Telemetry reconnects after read failures and stops reporting frozen physics packets as fresh.
- Failed telemetry saves preserve unrelated files; each saved run gets its own directory.
- AC setup generation refuses recommendations based on a baseline changed since analysis.
- Improved behavior/share identity validation and telemetry format checks.
- Bridge build fixes, improved window lifecycle/error handling, diagnostics, and update validation from the reliability audit.

## Install or update

Choose the installer EXE, or extract the portable ZIP into a new folder and launch AtomicDriftTuner.exe. Both packages are self-contained Windows x64 builds; testers do not need the .NET SDK.

For live AZOM use, update the included bridge: fully close SimHub, open ADT's Setup & Paths, choose Install / Repair Packaged Bridge, then restart SimHub. This package includes bridge v0.8.2-beta.1.

Existing tune and calibration formats are retained. Invalid or truncated files can now be refused rather than silently reset. Revert records expire after 24 hours; they are short-term recovery records, not permanent presets.

## Validation and beta limitations

The reliability pass passed 18 regression scenarios, including a range/finite-output sweep of 8,000 built-in combinations, and clean app/bridge builds. Initial hands-on testing was reported successful by the maintainer. This is a beta for wider hardware and driving validation, not a claim of universal compatibility.

The final portable package launched from a freshly extracted folder containing spaces. The installer upgraded an existing v0.7.3 Beta 2 installation successfully; all installed payload hashes matched the package and saved-data files were unchanged. Both packaged launches displayed v0.8.2-beta.1 and detected the existing AC car installation. Live bridge installation and hardware Apply/Revert were not re-run during the final packaging pass.

Share API server-side error-handling changes are in the source; installing the desktop beta does not deploy that service.
