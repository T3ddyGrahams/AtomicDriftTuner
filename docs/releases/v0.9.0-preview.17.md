# HUGE UPDATE — Atomic Drift Tuner v0.9.0-preview.17

**This is a HUGE update from the last public preview, v0.9.0-preview.3.** ADT now brings much more of the tuning workflow into Assetto Corsa, adds gearing recommendations and pedal-aware diagnosis, supports an adaptable touchscreen dashboard, and guides you from your first baseline through testing and comparing changes. It also introduces a choice of FFB software, including experimental MOZA Pit House support.

## The big additions

- **Content Manager / in-game companion:** ADT Companion provides connection status, Your Next Step, recording controls, findings, test planning and comparison feedback inside Assetto Corsa through Custom Shaders Patch. Install or update it directly from ADT's Remote page.
- **Save and apply car tunes from the pits:** Review a generated setup in desktop ADT, choose **Stage for in-game pits**, then explicitly **Save & Apply Tune** in the companion. Supported editable pit setups get uniquely named previous/changed saves, readback checks and a **Restore previous** action for the same session. Manual export/load remains available.
- **Capture the setup you are actually testing:** The companion can supply current numeric setup values, including unsaved pit edits where supported. ADT checks setup evidence periodically during recording and marks comparisons inconclusive when the evidence cannot support an improvement claim.
- **Gearing recommendations:** A first-version final-drive planner uses your chosen gear, speed range and desired RPM range to recommend a supported final drive and save a separate setup. It does not optimize individual gears or diagnose gearing from telemetry. Review the estimate and test one change at a time.
- **More context for telemetry diagnosis:** Throttle, braking and clutch observations build on ADT's existing phase-aware diagnosis, Desired Behavior profiles and driver-specific before/after history. Sustained, more extreme drift-angle goals help express what you want from the car; clearer summaries keep the next action understandable.
- **Touchscreen and Raspberry Pi dashboard:** An adaptable dashboard works across screen sizes, with fullscreen controls and a SimHub dashboard entry point. Use the PC's LAN address for a separate touchscreen or phone; desktop ADT remains the source of truth.
- **A clearer start-to-finish workflow:** Choose **Car tuning only** or **Car + FFB**, follow **Your Next Step**, and enable extra explanation/examples when needed. Instructions adapt to your software. New installations start with empty hardware/car selections and remember your own choices afterward.
- **Choose your FFB provider:** Use **SimHub / AZOM**, **MOZA Pit House**, or **Other wheelbase software / manual**. Existing users retain SimHub/AZOM by default. Switching providers starts a fresh comparison baseline while keeping saved history.
- **Recording and usability fixes:** Brief telemetry gaps have a recovery window of up to five seconds. The SDK folder browser now opens correctly from the embedded Setup & Paths page.

## Experimental MOZA Pit House support

The optional desktop SDK connection supports reading and explicitly applying **ten core controls**, with selected-value backups, readback checks and a reviewed restore action. It requires user-provided matching x64 MOZA SDK files and an SDK-compatible Pit House installation. Vendor SDK DLLs are **not bundled**.

**Real Pit House / wheelbase acceptance is still pending.** Unsupported settings remain manual. Selecting a provider or generating recommendations does not write to your wheelbase. Assetto Corsa's Controls → Force Feedback settings also remain a separate manual step. See [Pit House instructions](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/PITHOUSE.md).

The FFB provider addition and SDK folder fix preserve the existing tuning calculations. Car changes require an explicit load/apply action; ADT does not silently change the car while you drive.

## Downloads and upgrading

- **Recommended installer:** `AtomicDriftTuner-0.9.0-preview.17-setup.exe`.
- **Portable:** extract `AtomicDriftTuner-0.9.0-preview.17-portable.zip`, then run `AtomicDriftTuner.exe`. Do not run it inside the ZIP.
- **Optional separate companion download:** `ADTCompanion-0.4.0-preview.1.zip`. Both desktop packages already include this companion.
- **Checksums:** `SHA256SUMS-0.9.0-preview.17.txt`.

Both desktop packages are self-contained Windows x64 builds. Back up your ADT data and car setups, close ADT, then update. Existing local data is retained; installer and portable copies use the same data folders for the current Windows user. The downloads contain no developer settings, recordings, last-car profile, credentials or MOZA SDK binaries.

If using SimHub, close it before **Install / Repair Packaged Bridge**, then restart it. The bundled bridge is **0.9.0-preview.17**. Exit your AC session before **Remote → Install / Update Companion**, then start a new session and pair. Installing desktop ADT alone does not automatically install the companion into AC.

Upgrading from preview.3: choose your own rig/car and workflow once, verify the settings actually loaded in the game, and record a fresh baseline before judging a change. See the [guided walkthrough](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/GUIDED_WORKFLOW.md), [pit setup instructions](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/PIT_SETUP.md) and [touchscreen instructions](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/TOUCHSCREEN.md).

## Testing status

This is a **beta preview**, and the installer is **unsigned**. Development validation includes 179 regression scenarios, the existing 8,000 tuning-combination sweep, automated companion and touchscreen checks, and 60 passing UI assertions on the final SDK-folder fix. These automated checks do not establish real hardware or in-game compatibility.

Actual Pit House hardware read/apply/restore, the complete CSP pit save/apply/restore sequence and installer upgrade behavior remain field-test targets. Unsupported CSP/car combinations retain manual setup loading. An unresolved pit action blocks recording until its outcome is resolved. Before/after findings depend on comparable driving conditions and reliable evidence; they are not proof that a tune caused the result.

Use the [preview.17 testing checklist](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/testing/v0.9.0-preview.17-checklist.md) and [compatibility tracker](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/testing/v0.9.0-preview.17-compatibility.md). When reporting feedback, include the app version, car, relevant software/hardware, steps and expected/actual result. Keep pairing tokens and private recordings out of public reports.
