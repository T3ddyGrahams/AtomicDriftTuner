# Local preview.23 — Recording continuity

During a live test, the game continued advancing its physics packets while the saved recording repeatedly skipped roughly a quarter of a second. The recorder previously sampled the hub's latest frame on the desktop UI thread, so a busy interface could discard intervening frames.

The hub now retains every fresh frame it acquires for an active recording. The desktop drains that buffer in batches, using the original timestamps. Stop takes the final batch before analysis. No samples are interpolated, and the tuning engine, evidence thresholds and Desired Behavior requirements are unchanged. Desktop, companion and touchscreen share the corrected recorder; the companion package remains 0.4.0-preview.3.

The buffer holds up to 3,000 pending samples (about one minute at the requested 50 Hz). If the desktop cannot consume them, ADT preserves that prefix, marks the recording interrupted and explains the buffer overflow. Frozen packets are not counted twice. Real outages still produce gaps; a five-second outage, stream reset or detected car/track change ends the run with a reason.

## Test in Assetto Corsa

1. Start desktop preview.23 and the companion, using the same car and Desired Behavior profile as the previous test.
2. Record a representative 60–120 seconds with the companion and/or touchscreen connected. Include clean entries and direction changes when the requested behavior needs them.
3. Check Recording evidence details. The repeated quarter-second gaps should be gone; readiness still depends on the actual driving evidence and signal quality.
4. Stop and save, then record a second run. Confirm both runs remain separate and compare the saved continuity counts.
5. A real pause or telemetry loss must still be reported honestly. Ready to Review does not mean the tune is proven better, and recording continues until stopped.

Automated checks exercise the real background sampler with an anonymous physics map while the WPF thread is deliberately stalled, plus buffering, stop/save, repeat runs, duplicates, genuine gaps, restart detection, context changes, overflow and setup capture. Live-game confirmation remains pending. Old recordings and user settings are preserved; this build has not been published.
