# v0.8.3-beta.1 tester checklist

This round focuses on the new adaptive layout and icon, plus installation, saved tunes, telemetry, and optional integrations. Test what your setup supports; a partial report is useful. Record results for the exact release and configuration you used.

- [Download v0.8.3-beta.1](https://github.com/T3ddyGrahams/AtomicDriftTuner/releases/tag/v0.8.3-beta.1)
- [Installation and bridge guide](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/distribution/README-BETA-TESTERS.md)
- [Detailed beta testing guide](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/BETA_TESTING.md)
- [Compatibility tracker](v0.8.3-beta.1-compatibility.md)

## Before testing

Record Windows version, installer/portable build, previous ADT version if upgrading, wheelbase/rim/firmware, car/pack/version, and track. For each display, record resolution, portrait/landscape orientation, and Windows scaling percentage; include the affected window size or a screenshot for layout failures. Record AC, SimHub, AZOM, and bridge versions when used. Use `Unknown` for details you cannot find.

Use separate test profile and setup filenames, such as `beta083-test`, and keep existing tunes and baselines. For the per-car behavior test, record the original slider values so you can restore them afterward. Do not uninstall, delete saved data, or replace a working tune to create a “fresh install” test.

Use these result labels for each case:

| Result | Meaning |
| --- | --- |
| Pass | Performed the action and observed the expected result. |
| Fail | Performed the action and observed a different result; describe it. |
| Blocked | Could not complete an applicable case because of a problem or missing prerequisite; explain. |
| Not run | Have not attempted this case. |
| N/A | Does not apply to this configuration, such as an upgrade on a first installation. |

Do not count an untested case as passing. If different displays or cars give different results, report each configuration separately.

## Core flow

For a first report, choose one INSTALL case, then try SETUP-01, UI-01, SAVE-01, and SAVE-02. Add TEL-01 through TEL-03 if you can run Assetto Corsa. The remaining cases can be covered in later reports or by other testers.

### Installation and setup

Choose the installation case that applies; you do not need to test every package.

| ID | Action | Expected result |
| --- | --- | --- |
| INSTALL-01 | On a PC without an existing ADT installation, run the release installer and launch ADT. | App launches as v0.8.3-beta.1 without requiring Visual Studio or the .NET SDK; first-run Setup & Paths is usable. |
| INSTALL-02 | For an existing installation, note a saved profile, car behavior target, and saved setup; close ADT, install the update, then check those items. | v0.8.3-beta.1 launches and the existing saved items remain available with their original values. Record the previous version. |
| INSTALL-03 | Extract the portable ZIP into a fresh folder, preferably with spaces in its name, and run `AtomicDriftTuner.exe` from that folder. | v0.8.3-beta.1 launches without installation or the .NET SDK. Do not run inside the ZIP; portable testing does not require deleting existing ADT data. |
| SETUP-01 | Open **Setup & Paths**, verify your AC install/user-data paths and SimHub path if used, run **Test Everything**, then **Save & Continue**. Reopen the page. | Paths remain correct; results reflect what is installed. Missing optional SimHub/bridge components are identified without making basic ADT use impossible. |

Use your usual Windows scaling. Portrait, ultrawide, and mixed-scaling cases apply only if you have those displays; do not change your desktop configuration just to complete the checklist.

| ID | Action | Expected result |

| UI-01 | Resize ADT from a wide window to its smallest permitted size. Scroll Dashboard and AC Setup to the bottom. | Cards and sliders rearrange; Dashboard **Save Profile**, AC Setup **Save for This Car**, and **Save ADT Setup...** remain reachable. Disabled Save ADT Setup before generation is expected. |

| UI-03 | On an ultrawide display, maximize ADT, drag the navigation divider, and toggle the menu. | Navigation width changes on a wide window; show/hide works, and page content uses the remaining space without inaccessible actions. |
| UI-04 | With displays using different Windows scaling percentages, move a restored ADT window between them, then maximize and restore on each. | Text and controls scale for the destination display; the window and important actions remain reachable. Record both scaling values. |
| UI-05 | In a narrow window, use Tab/Shift+Tab and Enter/Space to open/close the navigation menu and reach a tool. Continue through its controls. | Focus is visible and follows usable controls. An open menu does not tab into the obscured page; hidden Dashboard actions do not receive focus while a tool is open. Report any control requiring a mouse. |
| UI-06 | At a narrow/short window size, visit Setup & Paths, Drive / Telemetry, Refine Tune, Share Codes, Tune / AZOM, Appearance, Diagnostics, and Updates. Check each tab and scroll wide tables horizontally. | Page content scrolls, table columns can be reached, and action rows/status remain accessible. Record the page and tab for any clipping; no hardware write or update is needed. |

### Saving and reopening

| ID | Action | Expected result |
| --- | --- | --- |
| SAVE-01 | Set the correct hardware/car context on Dashboard, **Generate Tune**, then **Save Profile** under a new test filename. Restart ADT and **Load Profile** from that file. | The saved hardware, car, and tuning inputs return; the file remains available after restart. Existing profiles are unchanged. |
| SAVE-02 | In AC Setup, note the current Desired Car Behavior values, choose a recognizable test target, and **Save for This Car**. Close/reopen the page and restart ADT with the same car selected. If available, also inspect a second car without saving to it. | The target persists for the intended car; the second car's saved target is unchanged. Restore the original values and save them when finished. |
| SAVE-03 | Use **Load Baseline** with an existing AC setup, then **GENERATE CAR SETUP**. If recommendations include at least one change, use **Save ADT Setup...** to save a separate test filename in the appropriate AC car/track setup folder. Refresh/load that file in ADT and check AC's setup menu for that car/track. | The generated setup can be reopened; the original baseline remains intact. If generation produces no changes, saving is unavailable: mark this case Blocked with that reason. No driving or overwriting the baseline is required. |
| SAVE-04 | After generating a setup, change a behavior slider or baseline selection and inspect **Save ADT Setup...**; regenerate once ready. | Saving the stale generated result is disabled until regeneration; saving becomes available when valid recommendations exist. |

### Telemetry

These cases need an installed, runnable Assetto Corsa session. Mark a missing prerequisite Blocked if you intended to test telemetry. Save useful sessions before starting another recording.

| ID | Action | Expected result |
| --- | --- | --- |
| TEL-01 | Load the intended car/track in AC. Open **Drive / Telemetry** (Telemetry Recorder), choose **Connect to Assetto Corsa**, and observe live data during normal driving. | Connection succeeds, the active car matches, and values update plausibly rather than staying frozen. |
| TEL-02 | Choose **Start Recording**, capture a normal run, then **Stop + Analyze**. Inspect status, observations, and any recommendation confidence. | Recording stops cleanly and reports captured frames/results. Limited evidence is identified; a short or unsuitable run need not produce an actionable recommendation. |
| TEL-03 | Choose **Save Session**, restart ADT, then open **Refine Tune** (Tuning Assistant) and **Refresh Sessions**. Select the saved session. | The session is listed with the correct car/context and can be reviewed; the save status identifies its JSON/CSV location. |
| TEL-04 | After saving the run, stop driving and end the AC session normally. Observe the disconnected/inactive state, then load a new session and reconnect using **Connect to Assetto Corsa** if needed. Record and save a short new run. | ADT does not continue presenting unavailable data as a live recording; reconnection works and the previous saved session remains available. Report any frozen values or recovery error. |

## Optional integration and driving checks

Only use integrations you already have or intentionally choose to test. Follow the [FFB safety guidance](https://github.com/T3ddyGrahams/AtomicDriftTuner/blob/main/docs/BETA_TESTING.md#ffb-safety): record original settings, keep power/emergency-stop controls accessible, and stop if behavior is unexpected. Do not apply an unreasonable recommendation or repeat unsafe behavior for a report.

| ID | Action | Expected result |
| --- | --- | --- |
| DRIVE-01 | Record a baseline on one car/track, note Desired Behavior and one recommendation you are comfortable applying, then capture a comparable run after that change. Review **Before / After** in Tuning Assistant. | Both sessions can be compared. Report **Better / Worse / No noticeable difference / Tradeoff** and what changed; successful comparison does not imply the recommendation improved the car. |
| BRIDGE-01 | Follow the installation guide: fully close SimHub, use **Install / Repair Packaged Bridge** in Setup & Paths, restart SimHub, and enable the bridge plugin if needed. | The packaged bridge is recognized and ADT reports its integration status. Record the running bridge version, SimHub version, and AZOM version. |
| BRIDGE-02 | In **Tune / AZOM > Live AZOM**, choose **READ LIVE AZOM** and record current values. Choose **Clear Selection**, then tick the **Apply?** checkbox for exactly one differing, supported, conservative change you understand. Choose **APPLY SELECTED** and confirm the dialog lists only one selected setting before proceeding. Inspect **Last Batch** and read live values again. | Only the checked supported change is applied; highlighting a grid row alone does not select it for Apply. Before/Target/After and Verified reflect the actual readback. An unverifiable change stops the operation and reports the problem. |
| BRIDGE-03 | After a successful BRIDGE-02, choose **REVERT LAST APPLY**, then read live values and compare them with the recorded originals. | The changed setting returns to its original value and the result is verified. If Apply failed, mark this Blocked rather than claiming a successful revert. |
| REMOTE-01 | In **Remote / iPhone**, leave remote writes disabled, choose **START REMOTE**, and pair a browser on the same private network using the displayed address/code. | Pairing and read-only viewing work; hardware writes remain unavailable. Record device/browser versions. Keep the service on your private network. |
| REMOTE-02 | Choose **STOP** in desktop ADT, then refresh the remote browser. | The remote service stops and the browser can no longer use the live interface; desktop ADT remains usable. |
