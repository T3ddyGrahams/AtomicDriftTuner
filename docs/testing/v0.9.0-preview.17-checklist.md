# v0.9.0-preview.17 testing checklist

Record your Windows, ADT, CSP/Content Manager, SimHub/AZOM or Pit House versions, wheelbase/rim, car/pack and display size. Test only the integrations you use. A blank checkbox means pending, not a failure.

## Install and first run

- [ ] Back up ADT data and car setups. Close ADT and install preview.17, or extract the portable ZIP to a new folder.
- [ ] Confirm version 0.9.0-preview.17. A new Windows-user profile starts without a preselected rig/car; an existing user's data remains available.
- [ ] Choose Car tuning only or Car + FFB. Confirm Your Next Step and optional extra explanations match the choice.
- [ ] Choose hardware/car, close ADT and reopen it. Confirm your choices are restored.
- [ ] Confirm controls, scrolling and save actions remain reachable on the displays you use.

## Baseline, one change, comparison

- [ ] Confirm the same car, driver and Desired Behavior profile. Record a representative baseline with the actual setup and FFB settings confirmed.
- [ ] Review phase/pedal observations and angle goals. Check that the summary and proposed next step are understandable.
- [ ] Review a supported gearing change; confirm that available ratios/ranges match the car. Apply one change and record another run under similar conditions.
- [ ] Save both runs, compare them, add feedback and reopen the history. Confirm changed identities/providers or missing setup evidence do not imply a proven improvement.
- [ ] Check a brief telemetry interruption and a longer loss. Report premature recording stops or unexpected recovery.

## Companion and touchscreen

- [ ] With AC closed, install/update Companion 0.4.0-preview.1 from Remote. Restart AC, pair, check connection/next-step status and start/stop/save a run.
- [ ] Enable current setup capture; confirm an unsaved pit edit is reflected where your CSP/car supports it. Check stale/disconnected evidence is visibly handled.
- [ ] Follow [PIT_SETUP.md](../PIT_SETUP.md): stage a reviewed plan, enter stationary editable pits, explicitly Save & Apply Tune, check saved files/readback, then test Restore previous in the same session.
- [ ] Check refusal for wrong car, changed baseline, moving car, recording, fixed/unsupported setup and unresolved action. Do not assume a failed apply rolled back automatically.
- [ ] Open the dashboard on a separate LAN device. Pair, use fullscreen and test recording controls at the device's actual screen size.

## Optional FFB provider tests

- [ ] Existing SimHub/AZOM settings and connection answers survive the upgrade. Update the packaged bridge with SimHub closed, then test connection and explicit Apply/Revert.
- [ ] Manual mode clearly explains which values to enter. Choosing a provider or generating recommendations alone changes no hardware settings.
- [ ] Pit House testers: follow [PITHOUSE.md](../PITHOUSE.md) with compatible software/SDK. Check folder browsing, Read, selected Apply, saved originals and reviewed restore against the physical device and Pit House UI.
- [ ] Switch providers and confirm old history remains while the new workflow requests a fresh baseline.

Submit results through GitHub Issues, including exact steps, expected/actual behavior and relevant versions. Do not attach credentials, pairing tokens or private recordings. See the [compatibility tracker](v0.9.0-preview.17-compatibility.md).
