# v0.9.0-preview.30 testing checklist

Record ADT/package, Windows, CSP/Content Manager, car/pack, FFB provider, wheelbase and display/browser versions as applicable. A blank checkbox means pending. Test the integrations you use and include the case IDs in your report.

## Upgrade and setup

- [ ] U1 — Back up local ADT data and car setups. Close ADT, install preview.30 or extract the portable ZIP to a new folder, and verify the version.
- [ ] U2 — Existing choices/history survive; a new Windows-user profile has no developer car/rig selected. Car tuning only / Car + FFB instructions match the chosen workflow.
- [ ] U3 — Controls, explanations and save actions remain reachable at your actual monitor size/scaling/orientation.
- [ ] U4 — With the AC driving session closed, install Companion 0.4.0-preview.4, then restart the session. Update the packaged SimHub bridge to preview.30 with SimHub closed if using it.

## Record, review and compare

- [ ] R1 — Verify car, driver, Desired Behavior and the actual loaded setup. Record representative driving. Short drift/corner sections add to the evidence counters.
- [ ] R2 — Check full/partial readiness and missing-goal instructions. The optional chime/toast occurs once; recording continues until Stop and Save.
- [ ] R3 — Save and start a second run with companion/touchscreen connected. Report premature stops, unexplained gaps or lost setup evidence.
- [ ] R4 — Review initiation, transition and pedal findings. Missing entries or unusable wheel-slip remain explained instead of fabricated.
- [ ] R5 — Review Gearing & ECU, test one change, save another comparable run, and reopen history. Changed targets, missing setup evidence and simultaneous ECU/gearing edits should not imply proven improvement.

## Gearing and car definitions

- [ ] G1 — Load the correct baseline; confirm detected gear count, fixed/individual/preset gearbox, and actual final-drive choices match the car.
- [ ] G2 — Choose tight-corner/sweeper gears and representative speeds. Check each goal's current/suggested RPM and any compromise or limiter exclusion.
- [ ] G3 — Switch mph/km/h without changing the physical target; save a default and reopen targets. Use a saved run's speeds when each selected gear has enough evidence.
- [ ] G4 — Review the provisional engine RPM estimate and manual override. Unknown/protected/custom data should explain its limits.
- [ ] G5 — Export a separate gearing setup and load it in AC. Confirm only the final-drive selection changed, then record a controlled comparison.
- [ ] G6 — Check packed/unpacked physics context. Unrelated conflicting definitions leave affected controls unchanged while valid settings work; relevant gearing conflicts remain blocked.

## In-game and optional integrations

- [ ] P1 — Capture the current setup through the companion or attach the actually loaded setup manually. Wrong/stale/unnamed evidence remains explicit.
- [ ] P2 — Follow [PIT_SETUP.md](../PIT_SETUP.md): regenerate, stage, then explicitly Save & Apply Tune while stationary in editable pits with no recording. Verify saved files/readback and same-session Restore previous.
- [ ] P3 — Wrong car, changed baseline, moving car, recording, unsupported setup and unresolved pit actions are refused. Check supported camber and anti-roll-bar limits.
- [ ] F1 — SimHub/AZOM: verify connection and explicit Apply/Revert with the updated bridge. Provider selection alone changes no settings.
- [ ] F2 — Pit House: follow [PITHOUSE.md](../PITHOUSE.md); report SDK/software/firmware and real Read/Apply/Restore results. A failed Read should leave ADT open and Apply disabled. Inspect uncertain writes before proceeding.
- [ ] D1 — On your LAN touchscreen/Pi, pair, use fullscreen, check readiness feedback and start/stop/save controls at the device's screen size.

Submit exact steps, expected/actual results and versions in GitHub Issues. Do not attach tokens, credentials or private recordings. See the [compatibility tracker](v0.9.0-preview.30-compatibility.md).
